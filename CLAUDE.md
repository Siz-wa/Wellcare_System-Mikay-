# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

WellCare Clinics & Laboratory (Dasmariñas branch) patient record management + appointment scheduling system. Capstone project. Laravel 12 + Inertia 2 + React 19 monolith — there is no separate API layer; controllers return `Inertia::render(...)` with props.

## Commands

```bash
composer dev          # serve + queue:listen + vite (concurrently) — the normal dev entrypoint
composer dev:ssr      # same, plus pail logs and the Inertia SSR server
composer setup        # install, key:generate, migrate, npm install, npm run build

composer test         # config:clear + pint --test + artisan test  (full suite)
php artisan test --filter=AppointmentTest   # single test file / test name
./vendor/bin/pest tests/Feature/DashboardTest.php

composer lint         # pint --parallel (PHP, writes)
npm run lint          # eslint --fix
npm run format        # prettier --write resources/
npm run types:check   # tsc --noEmit
composer ci:check     # everything CI runs: lint:check, format:check, types:check, test
```

Database is **MySQL** (`wellcare_db`) in local `.env`, despite `.env.example` shipping sqlite. Cache, queue, and sessions all use the `database` driver. Mail is `log`.

`php artisan migrate:fresh --seed` runs `DatabaseSeeder`, whose order matters: roles → doctors → HR → patients → appointments.

## Wayfinder-generated code — do not edit

`resources/js/actions/`, `resources/js/routes/`, and `resources/js/wayfinder/` are generated by the `@laravel/vite-plugin-wayfinder` plugin on every Vite run and are **gitignored**. They mirror `routes/web.php` and controller signatures. To change a URL a component uses, change the route/controller and let the plugin regenerate. Frontend imports these as `@/routes/...` (route-name style, most common) or `@/actions/...` (controller-method style). `@/*` maps to `resources/js/*`.

## Domain model

The critical distinction, and the source of most bugs in this codebase:

- **`User`** — a login account. Also doubles as the doctor record: `appointments.doctor_id` → `users.id`. There is no `Doctor` model (there is a `Doctorprofile` for display data).
- **`Patient`** — the actual person receiving care, with the medical record (allergies, diagnoses, documents). A single `User` can be guarantor for multiple `Patient`s.
- `Appointment` therefore carries **both** `user_id` (booking account) and `patient_id` (person seen). `patient_id` must stay in `$fillable` — dropping it makes records bleed across patients sharing an account. Relationship names are counterintuitive: `->patient()` returns the **User**, `->patientRecord()` returns the **Patient**.

`Patient::findOrCreateFromBooking()` dedupes on lowercased first + last name + `contact_number`, so the same person booking through different accounts resolves to one record.

### Appointment state machine

```
hmo coverage    → pending_hmo_approval → (HR approves) ─┐
other coverage  → requested ────────────────────────────┴→ (doctor confirms) → confirmed
                → (patient checks in, day-of) → checked_in
                → (doctor starts) → in_progress → (doctor finalizes) → completed
any pre-completed state → cancelled | no_show   (terminal)
```

The status column is a **MySQL ENUM**, so adding a state requires a migration that re-declares every value (see `2026_04_16_162417_add_pending_hmo_to_appointments_status.php`).

### Booking

All slot logic lives in `app/Services/BookingService.php`, not controllers. Rules encoded there: 2-hour minimum lead time, 3-month maximum, 10-minute `hold_expires_at` soft hold, 5-minute buffer between slots. Availability comes from `AvailabilityBlock` — a specific-date block overrides weekly recurring blocks for that date, and an `is_available: false` specific-date block blacks out the day entirely.

Two traps:
- `day_of_week` is stored in **MySQL `DAYOFWEEK` convention (1=Sun … 7=Sat)**, so Carbon's `dayOfWeek` needs `+1` on every lookup.
- Slots are cached under `slots:{doctorId}:{date}` for 60s. Any write that changes availability must call `bustSlotCache()`.

`bookSlot()` runs in a transaction with `lockForUpdate()` on both the slot and the per-patient/per-day conflict check, retried 3×.

### Notifications

Two parallel systems exist — be careful which one you touch:
- **`appointment_notifications` table** (`AppointmentNotification` model) is the live one. `HandleInertiaRequests` shares the latest 15 rows + unread count as Inertia props on every request; the bell UI reads those.
- `App\Services\NotificationService` dispatches Laravel `Notification` classes and targets by Spatie role. The stock `notifications` table is **not** the source for the bell.

### Roles & auth

Laravel Fortify handles auth; `spatie/laravel-permission` handles roles (`admin`, `hr`, `doctor`, `user`, `nurse`). Routes are gated by `role:` middleware in `routes/web.php`. `App\Http\Responses\Auth\LoginResponse` decides the post-login landing page per role (doctor → `/doctor/appointments`, hr → `/hr/dashboard`, else `/user/dashboard`). Auth views are registered in `FortifyServiceProvider::configureViews()` — note they point at `auth/login/index` and `auth/register/index`; the flat `auth/login.tsx` and `auth/register.tsx` are unused starter-kit leftovers.

Route ordering in `routes/web.php` is load-bearing: literal segments (`read-all`, `slots`, `patient-history`) are declared before `{id}`/`{appointment}` wildcards. Keep new literal routes above wildcards in the same group.

## Frontend conventions

Pages live under `resources/js/pages/<role>/<feature>/` and follow a consistent four-part shape:

```
<feature>/
  index.tsx  or  <feature>.tsx     # composition only — imports sections, no markup logic
  sections/                        # full-width page sections
  components/                      # feature-scoped components
  <feature>-data.ts                # all static copy, nav items, mock/seed arrays
```

Static text and lists go in the `*-data.ts` file, never inline in JSX. See `pages/generals/home/` and `pages/doctor/consultations/` as the reference implementations.

Three separate component layers coexist — pick deliberately:
- `resources/js/components/ui/` — shadcn/ui primitives (new-york style, lucide icons, `components.json`).
- `resources/js/design-system/` — the Wellcare-branded layer (`Button`, `Card`, `StatCard`, `Alert`, `Field`, …) exported from `@/design-system`. Prefer this for product UI.
- `resources/js/components/` — starter-kit app chrome (sidebar, nav, breadcrumbs).

Each role has its own dashboard layout and sidebar rather than a shared one: `pages/doctor/layout/`, `pages/hr/layout/`, `pages/user/layout/`. Public marketing pages use `@/layouts/app-gen-layout`.

CSS is Tailwind v4, configured entirely in CSS (no `tailwind.config.js`). `resources/css/app.css` imports `tokens.css`, `base.css`, `components.css` and defines the brand palette in `@theme` (`--color-wc-blue-*`, `--color-brand-*`, DM Sans / Bricolage Grotesque). Prettier is set to 4-space, single-quote, 80-col with the Tailwind class-sorting plugin.

React Compiler is enabled via `babel-plugin-react-compiler` — avoid manual `useMemo`/`useCallback` micro-optimizations.

- CRITICAL: ALWAYS use `search-docs` tool for version-specific Laravel documentation and updated code examples.

## Laravel 12 Structure

- In Laravel 12, middleware are no longer registered in `app/Http/Kernel.php`.
- Middleware are configured declaratively in `bootstrap/app.php` using `Application::configure()->withMiddleware()`.
- `bootstrap/app.php` is the file to register middleware, exceptions, and routing files.
- `bootstrap/providers.php` contains application specific service providers.
- The `app/Console/Kernel.php` file no longer exists; use `bootstrap/app.php` or `routes/console.php` for console configuration.
- Console commands in `app/Console/Commands/` are automatically available and do not require manual registration.

## Database

- When modifying a column, the migration must include all of the attributes that were previously defined on the column. Otherwise, they will be dropped and lost.
- Laravel 12 allows limiting eagerly loaded records natively, without external packages: `$query->latest()->limit(10);`.

### Models

- Casts can and likely should be set in a `casts()` method on a model rather than the `$casts` property. Follow existing conventions from other models.
